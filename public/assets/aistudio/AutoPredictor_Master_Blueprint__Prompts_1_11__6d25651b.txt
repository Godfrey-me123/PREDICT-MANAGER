SYSTEM ARCHITECTURE & CORE PURPOSE
================================================================================
1. Observation & Analysis Only:
   - AutoPredictor is strictly a live game-monitoring, crash-history recording,
     statistical pattern-recognition, and real-time Android notification system.
   - It MUST NOT place bets, change stakes, or automatically click game controls.
   - Users configure strategies; AutoPredictor watches the game, records actual
     crash multipliers, recognizes patterns, counts occurrences, tracks hourly
     sessions, and delivers real Android system notifications.

2. Primary Modules:
   1. Dashboard / Home
   2. Live Game Monitor
   3. Crash History
   4. Pattern Recognition
   5. Strategy Manager
   6. Hourly Analysis
   7. Notification Center
   8. Settings

3. Technical Stack & Separation of Concerns:
   - Kotlin + Jetpack Compose with Material 3 (clean LIGHT THEME as default).
   - Single authoritative Room database repository for permanent crash records,
     hourly summaries, and pattern tracking history.
   - StateFlow observable state management.
   - Separate live multiplier state from completed crash records.
   - Separate game detection from pattern analysis.
   - Separate pattern analysis from notification delivery.
   - Full Android 13+ lifecycle and permission compliance.

================================================================================

  Aviator-style games in Android browsers (Chrome, etc.) and native apps.

  content (e.g., Aviator, JetX, Spaceman) rather than hardcoding Aviator.
- Create a modular GameAdapter architecture:
  * gameId
  * displayedGameName
  * supportedPlatforms
  * detectGame()
  * detectLiveMultiplier()
  * detectCrashMultiplier()
  * detectMultiplierColor()
  * detectRoundState()
  * detectRoundIdentifier()
- Live Multiplier Detection Requirements:
  1. Distinguish a live climbing multiplier from a completed crash multiplier.
  2. Detect when a new round starts.

  4. Detect when the round crashes ("Flew Away" / round end).
  5. Capture the final multiplier at the exact moment of crash.
  6. Save each crash only once (strict deduplication).
  7. Detect missing or unreadable values and display "LIVE DETECTION LOST"
     rather than freezing or substituting a stale previous multiplier.
  8. Display last successful detection timestamp, detection confidence,
     platform name, and monitoring connection status.

  MediaProjection + OCR/image processing with explicit user consent for
  custom-rendered interfaces.

PROMPT 5 — ADVANCED STATISTICAL PATTERN RECOGNITION ENGINE
================================================================================
- Analyze completed crash records only (never live in-flight multipliers).
- Configurable Categories (user-editable thresholds):
  * Low: < 2.00x
  * Boundary: == 2.00x
  * Medium: > 2.00x and < 10.00x
  * Big Multiplier: >= 10.00x
- Pattern Detection Capabilities:
  1. Consecutive low crashes (e.g., exact chains of 14 consecutive crashes
     below 2.00x—never count scattered lows as one consecutive sequence).
  2. Repeated big multipliers & big multiplier clusters.
  3. Time gaps/intervals between big multipliers (e.g., 5 to 15 minutes apart).
  4. Alternating low and medium sequences.
  5. Repeated actual color sequences.
  6. Distribution of crash multipliers & count of lows before a big multiplier.
- Statistical Integrity:
  * Track total occurrences, first occurrence, most recent occurrence, average/
    shortest/longest intervals, current consecutive sequence, and historical
    frequency per game.
  * Never claim a pattern guarantees or predicts the next crash; use factual
    language ("Observed X times", "Repeated in this session").
