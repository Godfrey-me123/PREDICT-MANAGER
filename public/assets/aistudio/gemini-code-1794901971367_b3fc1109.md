Inspect `AutomationEngine.kt`, `GameDetection.kt`, `AccessibilityController.kt`, `StrategyConfig.kt`, and related data models to optimize the entire non-visual automation, execution, and strategy pipeline for **Predict Manager**. 

*Note: This implementation relies strictly on the existing core accessibility node inspection, calibrated target coordinates, and internal state machine—no floating visual hands overlay.*

Apply the following consolidated specifications:

## 1. STREAMLINED STAKE EDIT TO IMMEDIATE BET TAP FLOW
- **Remove Blocking Verification Between Stake & Bet:** In `AutomationEngine.kt`, when `applyStake(...)` reports success during the `BETTING_OPEN` phase, do not wait for a prolonged confirmation state on the input field. Proceed **immediately** to fire `clickBet(...)` if the site button state is ready (`IDLE_READY_TO_BET`). 
- **Atomic Action Sequence:** Combine stake entry acceptance and bet button triggering into a smooth, continuous pipeline. Once text replacement or button adjustment (`+` / `Double`) succeeds, dispatch the `CLICK_BET` gesture within 50ms to ensure the bet is placed before the betting window closes.

## 2. TIMEOUT PATTERN RE-VALIDATION & EXPIRY LOGIC
- **Post-Timeout Safety Check:** If a verification timeout occurs (e.g., the site takes longer than expected to transition to `BET_QUEUED`), evaluate whether the active strategy pattern and round state are still valid. 
- **Pattern Expiry Window (2+ Rounds Passed):** If the round has already advanced or **two or more subsequent multipliers/rounds have passed** since the strategy condition triggered, the automation must recognize that the pattern window is over. It must abort the pending action gracefully, reset the in-progress execution lock, and wait for a fresh pattern occurrence rather than placing a stale bet.

## 3. PRECISE LIVE MULTIPLIER MIRRORING & PHASE ISOLATION
- **Direct Live Extraction:** In `GameDetection.kt` and accessibility node parsers, ensure the central live multiplier (`currentMultiplier`) reads directly from the active flight node text without interpolation delay, smoothing jitter, or substituting stale values.
- **Strict Phase Isolation:** Keep the live climbing multiplier strictly separated from completed history ribbon items so that `gameState.currentMultiplier` accurately mirrors the real-time game state at all times, showing `0.00` or `LIVE DETECTION LOST` immediately if node reading is interrupted.

## 4. ACCURATE CASH-OUT DETECTION & SETTLEMENT
- **Live Cash-Out Recognition:** Continuously monitor site button states and node texts during `IN_FLIGHT` to instantly detect when a cash-out occurs (e.g., button transitions from `CASH_OUT` back to betting or displays collected status).
- **State Settlement:** When a cash-out is detected or confirmed, immediately record the payout, update active session profits, clear the active bet flag (`currentRoundBetActive = false`), and log the successful exit without waiting for the round to crash.

## 5. STRATEGY BET ATTEMPTS & MARTINGALE PROGRESSION SETTINGS
- **New Strategy Configuration Options:** Add parameters to `StrategyConfig.kt` and the Settings UI:
  1. `maxStrategyBetAttempts` (Integer, default: **2**): Defines how many times the app should attempt to place a bet for a given triggered strategy event before pausing.
  2. `isMartingaleEnabled` (Boolean, default: **false**): When enabled, if a bet results in a loss, the next stake automatically doubles (Martingale progression). If a win occurs, the stake resets to the base stake amount.
- **Execution Enforcement:** Integrate these options directly into `AutomationEngine.kt` and `StrategyEngine.kt` so that stake sizing and attempt counts strictly adhere to user configuration after every round outcome.
